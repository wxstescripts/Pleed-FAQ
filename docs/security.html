Security & AntiNuke

Pleed's security layer watches for mass-destructive actions (mass bans, channel deletion, role deletion, webhook spam) and automatically punishes whoever triggers them, plus a join gate for raid protection and rate limiting for command abuse.

Setting up AntiNuke

AntiNuke protects against compromised staff accounts or malicious bots by watching audit-log actions and punishing whoever crosses a threshold within a short window. Each module (bans, kicks, channel deletes, role deletes, emoji deletes, webhook creation, bot adds, vanity URL changes) has its own independent threshold and punishment.

  1. Run !antinuke enable to turn the system on for your server.
  2. Add trusted staff with !antinuke admin @user so they're exempt from punishment.
  3. Whitelist any bots/integrations that legitimately need to bulk-manage channels or roles with !antinuke whitelist @user_or_role_or_id.
  4. Tune individual modules, e.g. !antinuke ban on --threshold 3 --do ban punishes an account that bans 3+ members quickly by banning them back.
  5. Review your setup any time with !antinuke config or !antinuke list.
Bot permissions: AntiNuke needs View Audit Log, and Pleed's role must sit above the accounts it may need to punish, or it won't be able to act in time.

Join Gate / Anti-Alt

Screens new joins for very new or suspicious accounts (common in raid bot waves) and can hold them back from full access until they pass your checks.

Rate Limiting

Throttles command spam so a single user (or a compromised account) can't hammer moderation or economy commands to cause disruption.
