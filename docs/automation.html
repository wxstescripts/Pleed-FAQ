Automation

Automation

Build trigger-and-response rules without writing code: automations react to message content, reaction shortcuts respond to keywords with an emoji, and custom commands let you create your own server-specific commands.

Automations (trigger → response)

An automation matches messages against a trigger and fires a response — a reply, a reaction, or both — with fine-grained control over who and where it applies.

  1. !automation addresponse <name> <data> or !automation addreaction <name> <data> to create one.
  2. !automation match <automation_id> <match_type> — choose how strictly the trigger has to match (exact, contains, starts with, etc.).
  3. !automation filters, plus the dedicated !filters channels/roles/users and their block* counterparts, scope an automation to (or exclude it from) specific channels, roles, or members.
  4. !automation cooldown <automation_id> <seconds> and !automation chance <automation_id> <chance> stop a rule from firing on every single match.
  5. !automation priority decides which rule wins when more than one matches the same message.
  6. !automation stats / !automation resetstats show (or clear) how often each rule has triggered.

Manage the full list with !automation list [category], inspect one with !automation view <automation_id>, duplicate one with !automation clone, and toggle individual rules on/off with !automation enable / !automation disable without deleting them.

Auto-reacts & auto-responses (quick version)

For simple one-off cases you don't need the full automation builder:

  • !reactadd <emoji> <trigger> — react with an emoji whenever the trigger word appears (!reacts to list, !reactdel to remove).
  • !autorespond <trigger> <response> — reply with fixed text whenever the trigger appears (!autoresponses to list, !autoresponddel to remove).

Custom commands

Create your own server-specific commands under your existing prefix:

  • !addcmd <name> <response> — create a custom command.
  • !editcmd <name> <response> / !delcmd <name> — edit or remove one.
  • !testcmd <raw_text> — dry-run how a command body would parse before saving it.
  • !listcmds / !viewcmd <name> — browse what's already set up.

AutoMod (spam & word filtering)

AutoMod lives under Moderation — it handles blocked words, per-category punishment escalation, and strike tracking, separate from the trigger-based automations on this page.
