Moderation

Pleed's moderation suite covers the basics (kick, ban, timeout, warn) plus a full jail system, channel access control, alias commands, AutoMod, logging, and role tools — 134 commands in total.

The essentials

Standard actions work the way you'd expect from any moderation bot:

CommandDescription
!warn <member> [reason]Warn a member.
!timeout <member> [duration] [reason]Timeout a member — durations like 10m, 2h, 3d, 1w.
!kick <member> [reason]Kick a member from the server.
!ban <member> [reason]Ban a member from the server.
!softban <member> [reason]Ban, delete their last day of messages, then immediately unban.
!hardban <user_id> [reason]Ban by ID and store the user in a persistent hardban registry (they stay banned even if unbanned manually).
!purge <amount>Bulk-delete messages in the current channel.

Server lockdown

For active raids, !lockdown [reason] locks every channel for @everyone in one shot, with an interactive Confirm/Cancel step on the slash version so you don't lock down by accident. !unlockdown [reason] reverses it. For a single channel, use !lock [channel] [reason] and !unlock [channel] [reason] instead.

Jail System

Jailing is a softer alternative to banning: the member is stripped of their roles and given a restricted "jailed" role instead, so they stay in the server but can't interact until released.

  • !jail <member> [duration] [reason] — jail a member, optionally for a set duration (e.g. !jail @Bob 1h spamming). Shows a Confirm/Cancel prompt by default.
  • !sjail <member> [duration] [reason] — same as !jail but skips the confirmation step.
  • !unjail <member> [reason] — release a member from jail immediately.
  • !jailtime <member> <adjustment> — extend or shorten an active jail sentence.
  • !jailpanel [member] — open an interactive management panel for jail actions.
  • !jailconfirm on|off — toggle whether !jail requires the Confirm/Cancel step.
  • !jailtemplate add <name> <duration> [reason] — save a reusable jail template (e.g. a "spam" template with a preset duration and reason) so repeat offenses are one command.

Jail System — 11 commands

CommandDescription
!jail <member> [duration_or_reason] [reason]prefix (aka prison) ,jail @user [duration] [reason] — e.g. ",jail @Bob 1h spamming" Checks permissions and hierarchy first. If jail-confirm is off for this server, jails immediately via `apply_jail`. If it's on, shows a `JailConfirmView` and waits for a qualified staff member to press Confirm before actually jailing anyone.
!jailconfirmprefix (aka confirmjail) View or toggle whether `,jail` requires Confirm/Cancel buttons.
!jailconfirm offprefix (aka disable, disabled, false) No description available.
!jailconfirm onprefix (aka enable, enabled, true) No description available.
!jailpanel [member]prefix (aka jinfo, jailinfo) ,jailpanel [@user] — opens an interactive jail management panel. Shows server-wide jail/mute counts and config, plus `member`'s status if given. From there you can pick any member from the dropdown, browse the full jailed-members list, pull up a member's history, jail or unjail them — all with buttons, no more typing commands. See `JailPanelView` above for the UI itself.
!jailtemplateprefix (aka jtemplate, jailtemplates) ,jailtemplate — list saved quick-jail templates (or use ,jailtemplate add/remove). Templates are duration+reason presets (e.g. "spam" -> 1h, "Spamming in channels") that show up as one-click options in the ,jailpanel "Quick Jail" dropdown, so common jail reasons don't need to be typed out every time.
!jailtemplate add <name> <duration> [reason]prefix (aka set) ,jailtemplate add <name> <duration> <reason> — duration accepts `1h`/`3d`/etc, or `perm` for none.
!jailtemplate remove <name>prefix (aka delete) ,jailtemplate remove <name>
!jailtime <member> <adjustment>prefix (aka adjustjail) ,jailtime @user <adjustment> — change an active jail's expiry. `adjustment` can be `+1h` / `-30m` (relative to current expiry, or to now if currently permanent), `2h` / `3d` (reset to that duration from now), or `perm` / `permanent` / `none` (remove the expiry). See `apply_jail_time_adjust` for the exact rules.
!sjail <member> [duration_or_reason] [reason]prefix (aka silentjail) ,sjail @user [duration] [reason] — same as ,jail but skips the confirm buttons and the "you were jailed" DM. Permission and hierarchy checks still happen inside `apply_jail` itself.
!unjail <member> [reason]prefix (aka release) ,unjail @user [reason] — releases `member` immediately via `apply_unjail`.
